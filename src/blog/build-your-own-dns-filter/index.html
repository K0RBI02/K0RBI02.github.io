Build Your Own DNS Filter: Stop Your Smart TV From Phoning Home

The new television is bigger, sharper and somehow cheaper than the old one, even though everything else in the shop has become more expensive. A few evenings later you notice the "recommended for you" row knows exactly what you watched last night, including the film you streamed from a laptop over HDMI. That is not a coincidence. Many smart TVs recognise what is on the screen and report it, and that data is part of how the set pays for itself.

The good news: you can cut most of that chatter yourself, for every device in the house, with a small computer and an evening of work. This guide walks you through it.

Why the TV Is So Cheap

Most smart TVs ship with Automatic Content Recognition (ACR). The set takes small fingerprints of the picture at regular intervals, compares them with a database and learns what you are watching, whether it comes from an app, an antenna or a games console. Together with the apps you open and how long you stay, this builds a viewing profile that is used for advertising.

How much money is in it shows in the figures of the US manufacturer Vizio, which reported both sides separately. In 2022, its advertising and data business made around 296 million dollars of gross profit, the televisions themselves only about 16 million. The TV is the shop window; the data is the product. The topic is getting legal attention too: in December 2025, the state of Texas sued Samsung, Sony, LG, Hisense and TCL, arguing that their TVs collected viewing data without proper consent.

Quick win: Before building anything, switch ACR off in the TV's menu. The names vary by brand, for example Viewing Information Services on Samsung or Live Plus on LG, and it is usually hidden under privacy, terms or "smart features". Do the same for "interest‑based ads". It takes five minutes and stops the worst of it at the source.

The menu is a good start, but you have to trust it, and it does nothing about the other gadgets in the house. That is where your own DNS filter comes in.

How a DNS Filter Helps, and Where It Stops

Before a device can send data anywhere, it has to look up a name such as metrics.example.com. As DNS explained describes, that question goes to a resolver. If you run that resolver, you decide which names get an answer. Tracking and advertising domains get a polite "doesn't exist", everything else works as usual.

It helps to know the limits from the start:

  • It blocks names, not content. Ads that come from the same servers as the video, as in the YouTube app, can't be filtered by DNS.
  • Some devices bypass it. A device can use a hard‑coded resolver or encrypted DNS of its own. We cover what to do about that further down.
  • It can break things. Occasionally a blocked domain is needed for a login or an update. The query log shows you which one, and a single click unblocks it.

What You Need

  • A small computer that runs around the clock: a Raspberry Pi, a used mini PC, or the home server you already have. AdGuard Home needs very little; a Pi handles a whole household easily.
  • A fixed address for it: create a DHCP reservation in your router, so the box always gets the same address. In this guide it is 192.168.1.10.
  • Access to your TV's network settings, because that is where you point it at the new filter.

We use AdGuard Home here, a free, open‑source DNS filter with a clear web interface. Pi‑hole does the same job equally well; the steps are very similar.

1Step 1: Install AdGuard Home

There are three common ways. Pick the one that fits what you already have.

Option A: Directly on the system

On a Raspberry Pi or any Linux machine, the official install script sets everything up as a service:

curl -s -S -L https://raw.githubusercontent.com/AdguardTeam/AdGuardHome/master/scripts/install.sh | sh -s -- -v

Provided as is, without warranty. Check every line before you run it.

Option B: As a container

If your server already runs Docker (see VMs and containers), a compose.yaml keeps it tidy:

services:
  adguardhome:
    image: adguard/adguardhome
    container_name: adguardhome
    restart: unless-stopped
    ports:
      - "53:53/tcp"
      - "53:53/udp"
      - "3000:3000/tcp"
      - "80:80/tcp"
    volumes:
      - ./work:/opt/adguardhome/work
      - ./conf:/opt/adguardhome/conf

Provided as is, without warranty. Check every line before you run it.

Start it with docker compose up -d.

Worth knowing: On Ubuntu and some other systems, a built‑in service called systemd‑resolved already occupies port 53, and AdGuard Home can't start. The AdGuard Home documentation describes how to switch off its "stub listener"; do that first if the install complains that the port is in use.

Option C: As an app on Home Assistant

If you already run Home Assistant for your smart home, this is the easiest way, and the one our test setup uses. Not installed yet? Hands‑on #01 walks you through it.

  1. Open Settings → Apps and click Install app.
  2. Search for AdGuard Home, click Install, then Start.
  3. Click Open Web UI. You log in with your Home Assistant account, so you can skip the setup wizard in Step 2.

The filter's address is then the address of your Home Assistant device. Give it a static address in Home Assistant itself under Settings → System → Network, so the filter's address never depends on the router.

Tested by Korbi: this guide's setup
  • Filter: AdGuard Home as an app on Home Assistant, exactly as in Option C
  • TV: an LG television with webOS, DNS entered by hand as in Step 5
  • Tested: November 2026

2Step 2: Run the Setup Wizard

If you installed with Option A or B, open http://192.168.1.10:3000 in a browser. The wizard asks for three things:

  1. Web interface: keep port 80, so you can later reach the dashboard at http://192.168.1.10.
  2. DNS server: keep port 53 on all interfaces.
  3. An admin account: a proper password, ideally from your password manager.

3Step 3: Choose Where Answers Come From

AdGuard Home filters, but it still needs a resolver to ask for everything it lets through. Under Settings → DNS settings → Upstream DNS servers, enter two encrypted resolvers, one per line:

https://dns.quad9.net/dns-query
https://cloudflare-dns.com/dns-query

Provided as is, without warranty. Check every line before you run it.

Quad9 also blocks known malware domains, which is a nice extra layer. Select Parallel requests or Load balancing so one provider can fail without anyone noticing. With these addresses, your lookups leave the house encrypted, so your provider no longer sees every name either.

4Step 4: Add the Right Filter Lists

Under Filters → DNS blocklists, AdGuard Home already includes its own AdGuard DNS filter. Click Add blocklist → Choose from the list and add the ones that fit your household:

  • Perflyst and Dandelion Sprout's Smart‑TV Blocklist: a general list for TV tracking across brands, including the ACR services.
  • HaGeZi's LG webOS Tracker Blocklist or HaGeZi's Samsung Tracker Blocklist, depending on your TV's brand.
  • HaGeZi's Pro Blocklist for ads and trackers on all other devices. It is fairly strict, which is why the allow rules below matter.
  • HaGeZi's Threat Intelligence Feeds against malware and phishing domains.

Rule of thumb: Start with three or four lists, not twenty. Every extra list adds a little more risk that something you need stops working, and overlapping lists don't make you safer.

Keep Streaming Working

Strict lists sometimes catch a domain that a streaming app needs, and then the app shows an error instead of the film. To prevent that, add allow rules for the services you use under Filters → Custom filtering rules. A line starting with @@ means "never block this domain or anything below it". Our set from the test setup is in the box below.

Used by Korbi: allow rules for streaming
! Netflix
@@||netflix.com^
@@||netflix.net^
@@||nflxvideo.net^
@@||nflximg.net^
@@||nflxext.com^
@@||nflxso.net^
! Disney+
@@||disneyplus.com^
@@||disney-plus.net^
@@||bamgrid.com^
@@||dssott.com^
@@||disneystreaming.com^
! ARD / ZDF
@@||ardmediathek.de^
@@||ard.de^
@@||daserste.de^
@@||zdf.de^
! RTL+ / Joyn
@@||rtl.de^
@@||joyn.de^
! O2 TV (runs on waipu.tv)
@@||waipu.tv^
@@||o2.de^

Provided as is, without warranty. Check every line before you run it.

Lines starting with ! are comments. Add the services you actually use and leave out the rest, because every allow rule is a small hole in the filter.

Tested by Korbi: which streaming apps work
  • Works on the LG TV: ARD Mediathek and O2 TV (waipu.tv)
  • Not tested: Netflix, Disney+, ZDF, RTL+ and Joyn. Their rules are the services' usual domains, but nobody has checked them on this setup yet.

5Step 5: Point the TV at the Filter

Now the filter is running, but nobody uses it yet. The simplest way to start is the device you care about most: the television. Every smart TV lets you enter a DNS server by hand in its network settings. The menus differ by brand, but the path usually looks like this:

  1. Open Settings → Network (on some models General → Network).
  2. Choose the current connection, Wi‑Fi or cable, and open the IP settings or advanced settings.
  3. Switch the DNS setting from automatic to manual.
  4. Enter the address of your AdGuard box, 192.168.1.10. If there is a field for a second DNS server, leave it empty or enter the same address again, never a public resolver such as 9.9.9.9, or the TV will simply use that one and skip your filter.
  5. Save, then switch the TV off at the wall for a minute so it reconnects with the new setting.

Worth knowing: On some models, switching DNS to manual also switches the whole address setup to manual. Note down the address, subnet mask and gateway the TV shows before you change anything, and type them back in.

You can do the same for the whole household at once: in the router's settings, enter 192.168.1.10 as the DNS server it hands out to devices. Then every phone, laptop and gadget uses the filter automatically.

Worth knowing: If your connection uses IPv6, the router also announces a DNS server over IPv6, and many devices prefer it. Look for a separate IPv6 DNS setting in the router (on a FRITZ!Box it sits next to the IPv4 one) and point it at your filter too, or devices keep asking the router and quietly go around the filter.

6Step 6: Check That It Works

Open the dashboard and go to the Query log. Within minutes you should see requests from the TV's address. Many people are surprised at this point: a TV that is "off" in standby often makes hundreds of lookups an hour.

  • Give devices names under Settings → Client settings, so "192.168.1.47" becomes "Living room TV".
  • Look at what is blocked for that client. Red entries are the filter at work.
  • Unblock what you need. If an app stops working, filter the log by that device, find the blocked domain around the time of the error and click Unblock.
  • Set rules per device. Under the client settings you can apply stricter lists to the TV than to the work laptop, or block whole services for children's devices, which pairs well with parental controls on the network.

When the TV Tries to Go Around It

Some devices ignore the DNS server the router gives them and ask a resolver of their own, often Google's 8.8.8.8. In the query log, such a device stays strangely quiet. You can respond in two ways:

  1. Block outgoing DNS from the TV in the router. If your router has a firewall for individual devices, block ports 53 and 853 to the internet for the TV. Most devices then fall back to the server the router told them about.
  2. Put the TV in its own network. A guest or IoT network with strict rules, as described in segmenting your home network, limits what it can reach in the first place, and you see its traffic more clearly.

Against apps that use encrypted DNS over HTTPS inside their own traffic, a home filter can do little. That is the honest limit of this approach, and another reason to switch off ACR in the menu as well.

Keep It Running

Your filter is now critical infrastructure: if the little box fails, nobody in the house can open a website. A few habits keep it boring:

  • Turn on automatic updates for the operating system, and update AdGuard Home from its dashboard or by pulling the new container image.
  • Back up the configuration. It is a single file, AdGuardHome.yaml, in the configuration folder. Include it in your backups.
  • Know your emergency switch. Write down how to set the TV's (or the router's) DNS back to automatic. If the filter breaks while you are away, someone at home can restore internet in a minute.

For Small Businesses

The same setup works in an office, with a few extras: run two instances on separate machines, so a failed update doesn't stop the whole office, and document the setup for whoever takes over. Be careful with very aggressive lists, because a blocked domain in a business tool costs working time. In companies with a works council or employee monitoring rules, also check whether a query log with names of devices and websites is allowed to be kept, and how long.

Conclusion

Smart TVs are cheap partly because your viewing habits pay for them. Start by switching off ACR and interest‑based ads in the menu. Then install AdGuard Home on a small computer, add encrypted upstream resolvers and a handful of fitting filter lists, and enter its address as the DNS server on the TV, or in the router for the whole household, without a public resolver as backup. Check the query log, unblock what you need, close the bypasses for stubborn devices and keep a backup of the configuration. The television keeps working as before; it just talks a lot less about you.
