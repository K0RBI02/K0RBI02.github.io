15:T14c4,<p>You have one server and one public IP address, but several things to run on it: a blog, an internal editor, a dashboard, maybe a photo library. All of them want to be reachable under their own name and all of them should use HTTPS. Opening a different port for each is clumsy and insecure. If your provider shares that address with other customers, read <a href="/src/blog/cgnat-reaching-home-from-outside/">about CGNAT</a> first.</p>
<p>The good news: one small piece of software solves all of this at once. It is called a reverse proxy.</p>
<h2 id="what-a-reverse-proxy-does">What a Reverse Proxy Does</h2>
<p>A reverse proxy is the <strong>receptionist</strong> of your server. Every request from the internet arrives at it first, on the standard ports 80 and 443. It looks at which name was requested and passes the request on to the right service behind it:</p>
<ul>
<li><code>blog.example.com</code> → the blog, running on port 3000 internally</li>
<li><code>dev.example.com</code> → the editor and other tools, on other internal ports</li>
<li>anything unknown → rejected</li>
</ul>
<p>The services themselves are never directly reachable from the internet. Only the proxy is.</p>
<h2 id="https-without-the-hassle">HTTPS Without the Hassle</h2>
<p>HTTPS needs a certificate that proves the server really is <code>blog.example.com</code>. Not long ago, certificates were bought, installed by hand and forgotten until they expired. Today the free certificate authority <strong>Let's Encrypt</strong> and the <strong>ACME</strong> protocol automate everything:</p>
<ol>
<li>The proxy asks for a certificate for a name.</li>
<li>Let's Encrypt checks that you control that name, either by fetching a file from your server (<em>HTTP challenge</em>) or by looking for a DNS record you set (<em>DNS challenge</em>, required for wildcard certificates like <code>*.example.com</code>).</li>
<li>The certificate is issued and renewed automatically well before it expires. A <a href="/src/blog/monitoring-small-networks/">certificate check</a> catches the rare case where renewal fails.</li>
</ol>
<p>Certificate lifetimes are getting shorter across the industry, which makes automation not just convenient but necessary.</p>

<p>A complete Caddy configuration for two sites can be this short:</p>
<pre><code>blog.example.com {
    reverse_proxy localhost:3000
}

dev.example.com {
    reverse_proxy localhost:3100
}
</code></pre>
<h2 id="the-login-in-front-of-internal-tools">The Login in Front of Internal Tools</h2>
<p>Admin panels and editors should never be openly reachable. A reverse proxy can put a <strong>login in front of them</strong>, before a single request reaches the tool:</p>
<ul>
<li><strong>Basic authentication</strong>: a simple username and password at the proxy. Easy, but without two‑factor.</li>
<li><strong>Forward authentication</strong> with a single sign‑on service such as <em>Authelia</em> or <em>Authentik</em>: one login page with two‑factor authentication protecting all internal tools.</li>
<li><strong>Access only through a VPN</strong>: the internal names are not published at all and are only reachable for connected devices, see <a href="/src/blog/secure-remote-access/">reaching your network safely</a>.</li>
</ul>
<p>This is exactly the pattern for a setup like a public <code>blog.</code> with an internal <code>dev.</code> next to it: the blog is open to everyone, the tools sit behind the proxy's login.</p>
<h2 id="details-worth-getting-right">Details Worth Getting Right</h2>
<ul>
<li><strong>DNS first:</strong> each name needs a DNS record pointing to your server before a certificate can be issued (<a href="/src/blog/dns-explained/">DNS explained</a>).</li>
<li><strong>Pass on the real visitor address.</strong> Behind a proxy, every request seems to come from the proxy itself. Configure the proxy to send the original address in a header, and the application to trust it only from the proxy.</li>
<li><strong>Redirect HTTP to HTTPS</strong> and send security headers such as HSTS. Most proxies do this by default or with one line.</li>
<li><strong>Keep the proxy updated.</strong> It is the one component directly exposed to the internet.</li>
</ul>
<h2 id="conclusion">Conclusion</h2>
<p>A reverse proxy lets one server host many services under their own names, handles HTTPS certificates automatically and is the right place for a login in front of internal tools.
