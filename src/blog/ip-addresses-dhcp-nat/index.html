IP Addresses, DHCP and NAT: How Your Devices Get Online

What happens in the first second after a phone joins your Wi‑Fi, and why it explains so many everyday network problems.

A guest asks for the Wi‑Fi password, types it in, and a second later their phone is online. Nobody configured anything. Then one day the printer "disappears", a laptop shows "connected, no internet", or the instructions for a new gadget ask for its IP address, and suddenly that invisible second matters.

The good news: what happens in that second follows three simple ideas. Once you know them, most of these problems explain themselves.

The Address: Where a Device Lives

Every device on a network needs an IP address so that data knows where to go. An IPv4 address is four numbers from 0 to 255, separated by dots, for example 192.168.1.23.

An address comes with two companions:

  • The subnet mask says which part of the address is the network and which part is the device. At home it is almost always 255.255.255.0, also written as /24: the first three numbers name the network, the last one the device. That leaves room for 254 devices, which is plenty for a household.
  • The default gateway is the address of the router. Anything not on the local network, which is to say the entire internet, gets sent there.

Devices on the same network talk to each other directly. Everything else goes through the gateway.

Private and Public Addresses

Some address ranges are reserved for private networks and never appear on the internet:

  • 10.0.0.0 to 10.255.255.255
  • 172.16.0.0 to 172.31.255.255
  • 192.168.0.0 to 192.168.255.255

Your home network uses one of these. Common router defaults are 192.168.0.x, 192.168.1.x and 192.168.178.x (FRITZ!Box). Millions of homes use exactly the same addresses, and that is fine, because they never leave the building. Only your router's internet side has a public address, assigned by your provider.

DHCP: Addresses Handed Out Automatically

Nobody wants to type addresses into every phone. That job belongs to DHCP (Dynamic Host Configuration Protocol), and in almost every home the router is the DHCP server.

When a device joins the network, a short conversation takes place:

  1. Discover: the device calls out to the whole network: "I'm new, is there a DHCP server?"
  2. Offer: the router answers: "You can have 192.168.1.23."
  3. Request: the device replies: "I'll take it."
  4. Acknowledge: the router confirms and adds the details: subnet mask, gateway and which DNS server to use.

The address is not a gift but a lease with an expiry time. A device that stays around renews it quietly, usually halfway through. A device that leaves eventually frees its address for someone else. That is why the same laptop may have a different address next month, which is fine until something else relies on that address.

Worth knowing: The router also tells every device which DNS server to ask for names. That is why a wrong DNS setting in one place affects the whole household. More on that in DNS explained.

Fixed Addresses Without the Hassle

Printers, NAS systems and home servers are easier to find when their address never changes. You have two ways to do this:

  • DHCP reservation: in the router, you tie an address to the device's hardware address (its MAC address). The device keeps using DHCP but always gets the same address. Everything stays in one place, so this is the method to prefer.
  • Static configuration: you type the address into the device itself. It works, but choose an address outside the router's DHCP range, or one day the router will hand the same address to someone else. That conflict is a classic cause of a printer that keeps vanishing.

Private Wi‑Fi Addresses

Modern phones and laptops use a random hardware address for each Wi‑Fi network, to make them harder to track between networks. At home this can confuse a reservation or parental‑control rule, especially if the device changes its random address over time. If a reservation does not stick, look in the device's Wi‑Fi settings for an option like private address or randomised MAC and set it to a fixed address for your home network only.

NAT: Many Devices, One Public Address

Your home has many devices but usually just one public address. NAT (network address translation) makes that work.

When your laptop opens a website, the request leaves with its private address as the sender. The router swaps it for the public address, notes in a table which inside device started the conversation, and sends it on. When the answer comes back, the router looks up the table and passes it to the right device.

Two things follow from this:

  • Outgoing works by default, incoming does not. An unexpected connection from the internet has no entry in the table, so the router does not know where it should go and drops it. That is a welcome side effect for security, though it is not a replacement for a firewall.
  • Port forwarding is a manual table entry. It tells the router: "anything arriving on this port goes to that device." Every such entry is a door into your network, as described in the router security checklist.

Many providers now apply the same trick one level higher and share one public address among many customers, which is why port forwarding sometimes does nothing at all. The full story is in Can't reach home from outside?

Reading the Symptoms

What you see Likely cause Verdict
Address starts with 169.254 The device asked for an address and nobody answered Restart the router; check cable or Wi‑Fi; is DHCP switched on?
"Connected, no internet" but a normal address Gateway or DNS problem, or the line is down If the router's admin page loads, look at its internet status and DNS setting
Printer or NAS found one day, gone the next Its address changed Create a DHCP reservation
Random dropouts, "address conflict" messages Two devices with the same address, or two DHCP servers Static addresses outside the pool; only one DHCP server per network
Router shows a private address on its internet side A second router in front of it (double NAT) Put the first box in bridge or modem mode

Quick win: In the router's device list, give your important devices clear names and reservations. Five minutes of work saves a lot of guessing later.

A Note on IPv6

Everything above describes IPv4. IPv6 has so many addresses that NAT is not needed: every device gets its own public address, and devices often configure themselves without DHCP. The router's firewall takes over the protective role NAT used to play. Both run side by side on most connections today; see IPv6 at home and in the office.

For Small Businesses

The same three ideas apply, with a bit more discipline:

  • Plan the address range. Keep a block for fixed devices (servers, printers, switches, access points) and let DHCP use the rest. Write it down.
  • One DHCP server per network. A second router plugged in "just for more ports" is a frequent cause of chaos. Use a switch instead.
  • Separate networks for separate jobs. Guests, staff and cameras each get their own range and DHCP pool, as described in VLANs and managed switches.

Conclusion

Every device needs an address, a gateway and a DNS server. DHCP hands these out automatically as time-limited leases, and NAT lets all your private addresses share one public address. Give printers and servers a DHCP reservation instead of a typed-in address, keep to one DHCP server per network, and read 169.254 as "nobody answered". With that, the invisible first second becomes something you can check and fix.
