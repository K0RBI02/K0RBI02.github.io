15:T2468,<p>A guest asks for the Wi‑Fi password, types it in, and a second later their phone is online. Nobody configured anything. Then one day the printer "disappears", a laptop shows "connected, no internet", or the instructions for a new gadget ask for its IP address, and suddenly that invisible second matters.</p>
<p>The good news: what happens in that second follows three simple ideas. Once you know them, most of these problems explain themselves.</p>
<h2 id="the-address-where-a-device-lives">The Address: Where a Device Lives</h2>
<p>Every device on a network needs an <strong>IP address</strong> so that data knows where to go. An IPv4 address is four numbers from 0 to 255, separated by dots, for example <code>192.168.1.23</code>.</p>
<p>An address comes with two companions:</p>
<ul>
<li><strong>The subnet mask</strong> says which part of the address is the <em>network</em> and which part is the <em>device</em>. At home it is almost always <code>255.255.255.0</code>, also written as <code>/24</code>: the first three numbers name the network, the last one the device. That leaves room for 254 devices, which is plenty for a household.</li>
<li><strong>The default gateway</strong> is the address of the router. Anything not on the local network, which is to say the entire internet, gets sent there.</li>
</ul>
<p>Devices on the same network talk to each other directly. Everything else goes through the gateway.</p>
<h3 id="private-and-public-addresses">Private and Public Addresses</h3>
<p>Some address ranges are reserved for private networks and never appear on the internet:</p>
<ul>
<li><code>10.0.0.0</code> to <code>10.255.255.255</code></li>
<li><code>172.16.0.0</code> to <code>172.31.255.255</code></li>
<li><code>192.168.0.0</code> to <code>192.168.255.255</code></li>
</ul>
<p>Your home network uses one of these. Common router defaults are <code>192.168.0.x</code>, <code>192.168.1.x</code> and <code>192.168.178.x</code> (FRITZ!Box). Millions of homes use exactly the same addresses, and that is fine, because they never leave the building. Only your router's internet side has a <strong>public</strong> address, assigned by your provider.</p>
<h2 id="dhcp-addresses-handed-out-automatically">DHCP: Addresses Handed Out Automatically</h2>
<p>Nobody wants to type addresses into every phone. That job belongs to <strong>DHCP</strong> (Dynamic Host Configuration Protocol), and in almost every home the router is the DHCP server.</p>
<p>When a device joins the network, a short conversation takes place:</p>
<ol>
<li><strong>Discover:</strong> the device calls out to the whole network: "I'm new, is there a DHCP server?"</li>
<li><strong>Offer:</strong> the router answers: "You can have <code>192.168.1.23</code>."</li>
<li><strong>Request:</strong> the device replies: "I'll take it."</li>
<li><strong>Acknowledge:</strong> the router confirms and adds the details: subnet mask, gateway and which DNS server to use.</li>
</ol>
<p>The address is not a gift but a <strong>lease</strong> with an expiry time. A device that stays around renews it quietly, usually halfway through. A device that leaves eventually frees its address for someone else. That is why the same laptop may have a different address next month, which is fine until something else relies on that address.</p>
<blockquote>
<p><strong>Worth knowing:</strong> The router also tells every device which DNS server to ask for names. That is why a wrong DNS setting in one place affects the whole household. More on that in <a href="/src/blog/dns-explained/">DNS explained</a>.</p>
</blockquote>
<h3 id="fixed-addresses-without-the-hassle">Fixed Addresses Without the Hassle</h3>
<p>Printers, NAS systems and home servers are easier to find when their address never changes. You have two ways to do this:</p>
<ul>
<li><strong>DHCP reservation:</strong> in the router, you tie an address to the device's hardware address (its MAC address). The device keeps using DHCP but always gets the same address. Everything stays in one place, so this is the method to prefer.</li>
<li><strong>Static configuration:</strong> you type the address into the device itself. It works, but choose an address <em>outside</em> the router's DHCP range, or one day the router will hand the same address to someone else. That conflict is a classic cause of a <a href="/src/blog/network-printers-scanners/">printer that keeps vanishing</a>.</li>
</ul>
<h3 id="private-wifi-addresses">Private Wi‑Fi Addresses</h3>
<p>Modern phones and laptops use a <strong>random hardware address</strong> for each Wi‑Fi network, to make them harder to track between networks. At home this can confuse a reservation or parental‑control rule, especially if the device changes its random address over time. If a reservation does not stick, look in the device's Wi‑Fi settings for an option like <em>private address</em> or <em>randomised MAC</em> and set it to a fixed address for your home network only.</p>
<h2 id="nat-many-devices-one-public-address">NAT: Many Devices, One Public Address</h2>
<p>Your home has many devices but usually just one public address. <strong>NAT</strong> (network address translation) makes that work.</p>
<p>When your laptop opens a website, the request leaves with its private address as the sender. The router swaps it for the public address, notes in a table which inside device started the conversation, and sends it on. When the answer comes back, the router looks up the table and passes it to the right device.</p>
<p>Two things follow from this:</p>
<ul>
<li><strong>Outgoing works by default, incoming does not.</strong> An unexpected connection from the internet has no entry in the table, so the router does not know where it should go and drops it. That is a welcome side effect for security, though it is not a replacement for a firewall.</li>
<li><strong>Port forwarding is a manual table entry.</strong> It tells the router: "anything arriving on this port goes to that device." Every such entry is a door into your network, as described in the <a href="/src/blog/router-hardening/">router security checklist</a>.</li>
</ul>
<p>Many providers now apply the same trick one level higher and share one public address among many customers, which is why port forwarding sometimes does nothing at all. The full story is in <a href="/src/blog/cgnat-reaching-home-from-outside/">Can't reach home from outside?</a></p>

<h2 id="a-note-on-ipv6">A Note on IPv6</h2>
<p>Everything above describes IPv4. IPv6 has so many addresses that NAT is not needed: every device gets its own public address, and devices often configure themselves without DHCP. The router's firewall takes over the protective role NAT used to play. Both run side by side on most connections today; see <a href="/src/blog/ipv6-at-home-and-in-the-office/">IPv6 at home and in the office</a>.</p>
<h2 id="for-small-businesses">For Small Businesses</h2>
<p>The same three ideas apply, with a bit more discipline:</p>
<ul>
<li><strong>Plan the address range.</strong> Keep a block for fixed devices (servers, printers, switches, access points) and let DHCP use the rest. Write it down.</li>
<li><strong>One DHCP server per network.</strong> A second router plugged in "just for more ports" is a frequent cause of chaos. Use a switch instead.</li>
<li><strong>Separate networks for separate jobs.</strong> Guests, staff and cameras each get their own range and DHCP pool, as described in <a href="/src/blog/vlans-managed-switches/">VLANs and managed switches</a>.</li>
</ul>
<h2 id="conclusion">Conclusion</h2>
<p>Every device needs an address, a gateway and a DNS server. DHCP hands these out automatically as time-limited leases, and NAT lets all your private addresses share one public address. Give printers and servers a DHCP reservation instead of a typed-in address, keep to one DHCP server per network, and read <code>169.254</code> as "nobody answered".
